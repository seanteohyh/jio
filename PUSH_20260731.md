## 4. What changed, and the reasoning worth keeping

### Verified against the code, not assumed

- **Office coordinates.** `map/page.tsx` and `scripts/enrich-walktimes.ts` both
  read offices from the database; `DEFAULT_OFFICE` in `constants.ts` is only a
  fallback. The Supabase edit was authoritative, so no code change was needed.
  The enrich script **skips already-cached pairs**, which is why the cache had
  to be deleted before re-running.
- **Home's "Start a Jio" was not a bug.** Its own comment described a
  deliberate quick path, with `/events/new` as the full form. It had simply
  drifted — no date field, no invitees, no place search. Both now render the
  same `JioForm`, so parity is structural rather than remembered.
- **`/welcome` firing twice.** `nameAuth.signInWithName` wrote `display_name`
  but never `onboarded_at`, and Home redirects whenever that is null. It now
  stamps it at sign-in. `/welcome` still exists for `email` mode, where people
  genuinely arrive without a name.
- **`DELETE /api/places/[id]` had no permission check** beyond being signed in.
  Nothing in the UI called it, so it was never reachable through the app, but
  the endpoint was live. Now admin-only, pointing at `/block` instead.
- **Migration 026** drops cached walk times when a place *or* an office moves.
  Deleting rather than recomputing is deliberate: `/places` sorts `NULLS LAST`,
  so a missing time reads as "we don't know yet" while a stale number reads as
  fact. This matters more now that anyone can drag a place's pin.

### Decisions taken during the session

| Decision | Choice |
|---|---|
| Kaki invites | Snapshot members into `event_invitees` **and** keep `kaki_id` for provenance — same shape as migration 019 |
| Suggest | Button on `/places`, not a tab or a default sort; route stays live |
| Reviews | Per-visit, editable and deletable |
| Saved places | Segmented All/Saved control on `/places` |
| Place deletion | Admin only; blocking stays creator-or-admin with a reason |
| Nav | Today's destinations kept, design doc's styling applied |

### Two deliberate deviations from the design doc

1. **Nav icons.** §5.3 maps Jios → `Users`. Kakis needs a slot too, and two
   people-shaped glyphs side by side at 20px are hard to tell apart, so Jios
   takes `CalendarDays` and `Users` goes to Kakis. One-line swap if unwanted;
   noted in `BottomNav.tsx`.
2. **Nav labels.** Shipped as "Kaki" and "You" rather than the doc's fixed
   vocabulary "Kakis" and "Profile".
